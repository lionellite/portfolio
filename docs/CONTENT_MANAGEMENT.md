# Guide de gestion de contenu

Ce guide complète le [guide d’administration](../ADMIN_GUIDE.md). Il décrit les bonnes pratiques de publication pour conserver un portfolio précis, crédible et facile à parcourir.

## Profil et parcours

Le profil public doit rester concis et actualisé. Renseignez un titre professionnel explicite, une biographie centrée sur vos expertises actuelles, une adresse de contact stable et des liens qui mènent vers des profils réellement maintenus.

| Élément | Recommandation |
| --- | --- |
| Photo | Utilisez un portrait net, recadré verticalement, en PNG, JPEG, WebP ou AVIF. |
| Biographie | Présentez votre domaine, vos méthodes et les sujets techniques que vous maîtrisez. |
| Compétences | Regroupez-les par domaine et évitez les listes trop longues. |
| Expériences | Décrivez le contexte, votre rôle, l’impact technique et les outils mobilisés. |
| Formations | Gardez les intitulés officiels, l’établissement et l’année de fin si disponible. |

## Créer un projet

Un projet publié doit pouvoir être compris sans consulter le code source. Le titre nomme le produit ou le problème résolu. Le résumé explique le résultat en une ou deux phrases. La description détaillée précise le contexte, les choix techniques, votre contribution et les limites éventuelles.

| Champ | Règle de qualité |
| --- | --- |
| Identifiant URL | Minuscules, chiffres et tirets uniquement ; il doit rester stable après publication. |
| Technologies | Séparez les technologies par des virgules, sans répéter les variantes. |
| Image de couverture | Préférez un schéma d’architecture, une interface, une carte de données ou un visuel directement lié au projet. |
| Publication | Ne cochez cette option qu’après relecture de la page publique. |
| Mise en avant | Réservez-la aux projets les plus représentatifs du portfolio actuel. |

## Écrire un article

L’éditeur riche permet les paragraphes, mises en valeur, listes, citations, blocs de code et liens. Le HTML est nettoyé avant enregistrement afin de retirer les balises et URL non sûres.

Pour chaque article, commencez par un problème concret, exposez le raisonnement ou la méthode utilisée, puis terminez par les résultats, limites ou points à retenir. Les tags doivent décrire un thème de recherche, une technologie ou une pratique : par exemple `DevOps`, `Python`, `Observabilité` ou `API`.

> Un article non publié reste un brouillon. Vérifiez le titre, l’extrait, les tags et le rendu mobile avant d’activer la publication.

## Traitement des messages

Les messages reçus sont accessibles dans l’administration. Répondez depuis l’adresse associée au profil ou via le lien e-mail du tableau de messages. Les messages contiennent des données personnelles ; ne les copiez pas dans un dépôt, un ticket public ou une capture partagée.
